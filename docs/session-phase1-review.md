## 实现边界与已有数据

- 这是本地演示身份选择，用户可以主动选角色或传入已知 X-User-Id。没有密码、签名会话或 JWT，不构成生产身份认证；当前未实现 PostgreSQL、连接池、RLS 或多 Pod 部署。
- 同会话运行互斥仅限单 Python 进程；本地应使用单 worker。多进程需要跨进程锁/任务队列与共享服务端数据库。
- 原始裸 session_id checkpoint 没有可靠的 worker 信息。本次不自动迁移或删除这些旧图记录，避免错误归属；已有消息表记录仍可展示，新请求使用新的隔离 thread。旧上下文不会自动延续，后续若需要迁移应先备份数据库并单独核对。
- 不再自动读取旧 pickle 类型 checkpoint；也不会删除现有数据库。恢复验证覆盖了重建实例和两个独立 Python 进程的写入/恢复/继续对话；未重启用户当前运行的服务进程。
- 失败/取消请求可能留下已提交的用户消息，未实现整轮消息与 graph 的分布式原子提交。后端互斥防止正常请求期间删除后被在途任务重新写入。
- 面试材料中的“工业级”“平滑切换 PostgreSQL”“NFS 必现锁或损坏”“全部稳定”等表述不能作为已验证事实。本次交付以代码和本说明的实现边界为准，不冒称生产验证。

### 执行中发现并继续修复的问题

1. `支付系统频繁 OOM` 漏过告警快速路由：在明确的动宾告警规则中补上“系统”实体，不更改演练/否定过滤逻辑。
2. RAG SSE 的 done 事件没有最终答案：补齐最终答案字段，保证与消息表记录一致。
3. 流式异常重复发送两条 error：统一由 API 外层发出一个终止错误。
4. 连续 AIOps 任务会沿 reducer 累加上次 past_steps：用 LangGraph Overwrite 显式重置任务执行步骤，新任务不混入旧任务记录。
5. 前端忽略 done.answer：完成时采用服务端最终报告，避免把中间诊断 JSON 当成最终回答。
6. 普通 HTTP 局域网地址下 randomUUID 可能不可用：保留安全随机字节生成 ID 的兼容路径。
